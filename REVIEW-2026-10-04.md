# PrivacyWorm review + UX pass
Date: 2026-10-04

Goal: make PrivacyWorm something a non-technical person can install and use
regularly without pain - one-line install, no git, no Python knowledge, and a
guided flow from "who are you" to "it's gone".

## What I found

### Broken for anyone installing normally
1. **`pip install .` shipped zero brokers.** Playbooks lived outside the
   package, so a non-editable install scanned nothing and reported every
   broker "clean". Fixed: the wheel now bundles them as `privacyworm/playbooks/`
   (repo layout unchanged for contributors).
2. **CI was red on `main`.** `test_rescan_scheduling` hard-coded 2026-07-22 as
   "the future". Fixed with a relative date.
3. **Mugshot commands crashed with encrypted state.** They opened `StateDB()`
   without the passphrase. Fixed: shared unlock helper.
4. **README promised CAPTCHA handling that didn't exist.** A blocked page
   silently produced "clean". Fixed: block-page detection, reported as
   "couldn't check", with a retry in a visible window.

### Correctness / safety
5. Search URLs weren't URL-encoded ("Mary Ann", "O'Brien" broke) and still
   used `str.format` on playbook text. Fixed: only plain placeholders allowed
   (validated at load time too), values encoded.
6. Aliases were collected but never used for matching. Fixed.
7. Listings with no link stored `NULL` URLs, which slip past the UNIQUE
   constraint and re-prompted every scan. Fixed: fall back to the search URL.
8. Files in `~/.privacyworm` were world-readable on Linux (old review item 9,
   never done). Fixed: folder 0700, files 0600, atomic writes for encrypted blobs.
9. `review` treated a stray Enter as "reject" (permanently). Now Enter defers.
10. Review showed *your own* name and city as "Match:" for every listing,
    which looked like evidence but wasn't. Replaced with plain-English
    "Strong match - matched on your name, city and age".
11. Success was "form submitted". Now a later clean scan marks a requested
    listing **gone**, and a gone listing that returns is flagged **reappeared**
    (old review item B). Blocked/failed scans change nothing.
12. "0 results" on a page that still shows your name now reads as "couldn't
    read the results - the site changed" instead of "clean" (stale selectors).

### UX
- The only path was a 6-command sequence plus `pip`, `playwright install`, and
  environment variables for email and IMAP passwords.
- The passphrase was asked repeatedly; social/mugshot asked separately.
- Headless form-filling + auto-submit can't pass the CAPTCHAs most broker
  opt-out forms have.

## What changed

- **One-line installers** (`install.sh`, `install.ps1`, double-click
  `install.cmd`). They fetch `uv`, which installs Python if needed and the app
  from the GitHub archive - no git. Re-run to update. Adds an app-menu entry.
- **Guided mode**: run `privacyworm` (or the shortcut) and answer questions.
  First run: welcome → 3-step profile interview with validation (state names,
  ZIP, phone, DOB formats) → passphrase → reminders → first check-up.
  Every run: unlock once, one-glance status, menu.
- **Check-up** = scan with live progress → "Is this you?" review (with
  `o` to open the page) → assisted removal: forms open pre-filled in a visible
  window and you do the last click; email opt-outs open as a draft in your own
  mail app (no SMTP setup); manual brokers open with instructions.
- **Reminders**: daily OS job (Task Scheduler / launchd / systemd or cron)
  that opens PrivacyWorm only when a check-up is due. Reads a date-only file;
  never touches the passphrase.
- **Browser**: uses installed Chrome/Edge first; downloads Chromium only if
  neither exists. `privacyworm doctor` diagnoses problems.
- New commands: `checkup`, `setup`, `doctor`, `reminders`, `update`,
  `uninstall`. `optout` is assisted by default in a terminal (`--no-assist`
  for the old behaviour).
- New installs encrypt the listing history by default (same passphrase).
- IMAP app password can be saved inside the encrypted profile instead of an env var.
- CI: new job runs the real installer on Ubuntu, macOS and Windows.

## Still true / next steps

- **The biggest gap is unchanged: no playbook has been live-verified.**
  The selectors are fixture-only, so against real sites expect many
  "couldn't read the results". The UX now says so honestly and offers to open
  the page, but the real fix is a live pass over the 10 brokers.
- Windows/macOS shortcut and scheduler code is exercised by the new CI job,
  not by hand. Worth one manual run on each.
- Social bulk-delete still needs a Reddit/Twitter developer app ID per user.
- No signed releases. If you want a true double-click experience (no
  terminal at all), the next step is a GitHub Release with the installer
  files attached, or a PyInstaller/Briefcase build.
